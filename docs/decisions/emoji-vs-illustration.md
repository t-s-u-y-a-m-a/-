# デザイン方針 最終判断たたき台 ― 絵文字 → 実イラスト差し替えの是非

作成日: 2026-09-10
対応タスク: `docs/TASKS.md` グループC「C3: 絵文字ベースの表示を実イラストに差し替えるかどうかの最終判断」
ステータス: ドラフト(意思決定待ち)

## 1. 背景

現在の「てんのお世話ゲーム」(および付属ミニゲーム『三びきのくま』)は、
キャラクターの表情・仕草・UIアイコンのほとんどを絵文字で表現している。
一方で家画面の家族写真(`assets/images/papa-baby.png` / `mama-baby.png`)は
既に実写画像を使っており、**表現手法が混在した状態**にある。

`docs/TASKS.md` はこの点を「複数の企画書(A1〜A6)が出揃ってから判断すべき事項」
として明記しており、本ドキュメントはその判断のためのたたき台である。
A1〜A6(大きなかぶ・ももたろう・三びきのこぶた・最終章・絵本システム・世界マップ)
の企画書がまだ揃っていないため、現時点の判断は暫定である。

## 2. 現状の棚卸し

### 2-1. 絵文字で表現されている要素

コード内(`index.html` / `script.js` / `stories/three-bears/*`)を確認したところ、
以下の用途で絵文字が使われている。

| 用途 | 例 | 該当箇所 |
|---|---|---|
| 赤ちゃん「てん」の表情(乱数で変化) | 😊 😴 🥺 😣 🙂 😆 😮 😢 😑 😐 😲 😟 | `baby-face` (お世話画面) |
| てんの仕草・鳴き声演出 | ♪ ✨ 💛 ♡ | `baby-gesture` / `baby-speech` |
| くまの表情(『三びきのくま』) | 🐻 | 3匹のくま共通 |
| お世話アクションのアイコン | 🍼 🤗 😴 💩 🌡️ 🎈 | `care-grid` ボタン |
| ホーム画面のナビゲーション | 🏠 📒 📖 🗺️ 🔒 | `home-menu` |
| 観察・演出系のUI | 🔎 | 観察ボタン |

絵文字の総使用箇所は29種類・約60箇所(ホーム/お世話/三びきのくまの3画面合計)。
**このうち赤ちゃん・くまの「表情」は乱数で毎回変化する仕様**(design spec より、
「同じ強さでも毎回微妙に反応が変わる」)であり、単純な静止画差し替えでは済まない。

### 2-2. 既に実写・イラスト素材がある要素

| 用途 | 素材 | 備考 |
|---|---|---|
| 家画面の家族写真 | `assets/images/papa-baby.png`, `mama-baby.png` | 実写(または実写相当)を既に採用 |

つまり「家族=実写」「本人(てん)・くま=絵文字」という**手法の分裂が既に発生している**。

## 3. 論点

1. **動的表現との相性** — 表情・仕草はランダムに変化する設計。絵文字なら実装コストほぼゼロで
   バリエーションを出せるが、イラストにする場合は状態の数だけ静止画(または差分パーツ)が必要になる。
2. **今後増えるキャラクター** — A1〜A6で追加予定の「かぶ」「ももたろう」「こぶた」等、
   キャラクターは今後も増える。イラスト化する場合、キャラクターが増えるたびに発注・作画コストが発生する。
3. **既存の実写要素との統一感** — 家族写真は実写。絵文字比率が高いままだと、
   家画面(実写)とお世話画面(絵文字)でトーンが分裂して見える可能性がある。
4. **予算・体制** — 外部イラストレーター起用の要否、または生成AIでの作画運用の是非。
5. **スケジュール** — A1〜A6の完成を待ってから着手すると全体のリリースが後ろ倒しになる。
   先行して一部だけ着手する余地があるか。

## 4. 選択肢比較

| 選択肢 | 実装・発注コスト | 動的表現力 | 既存実写との統一感 | 保守性(新キャラ追加時) | 着手タイミング |
|---|---|---|---|---|---|
| **A. 現状維持(絵文字ベース)** | なし | 高(乱数差し替えが容易) | 低(家族写真だけ浮く) | 高(コストゼロ) | 即時 |
| **B. 主要キャラのみイラスト化**(てん・くま等の顔だけ差分イラスト、UIアイコンは絵文字のまま) | 中 | 中(表情差分を用意すれば乱数対応可) | 中〜高 | 中(新キャラ追加ごとに差分発注) | A1〜A6の主要キャラが固まり次第 |
| **C. 全面イラスト化**(キャラ・UIアイコンすべて統一デザインに置換) | 高 | 低〜中(差分数が最も多い) | 高 | 低(発注量が最大) | A1〜A6完成後 |

## 5. 暫定所見

- 絵文字は「開発者が用意した仮の記号」ではなく、**乱数で毎回違う反応を返す**という
  ゲーム性そのものと相性が良い(design spec の「予測できないふれあい」という狙いに合致)。
  全面イラスト化(選択肢C)は表現の幅と引き換えに、この乱数演出の実装コストを大きく増やす。
- 一方、家画面はプレイ時間が短く反応バリエーションも不要なため、
  **家画面まわり(ホームメニューのアイコン、キャラの顔アイコンなど)から段階的に
  イラスト化する(選択肢Bの一部)** のはコストが低く着手しやすい。
- 「てん」「くま」等、反応が乱数で変化する画面については、
  A1〜A6で今後増えるキャラクターの傾向(人型か、動物か、物か)が見えてから
  差分イラストの設計方針(何パターン必要か)を固めるのが安全。

以上より、**現時点の暫定推奨は選択肢B(主要キャラのみ段階的イラスト化)**とし、
着手はA1〜A6の企画書が出揃い、キャラクターの全体像が見えてからとする。
